# Section 2 evidence update — 25 September 2026

This is a follow-up to the 25 September leadership dossier, not a replacement for its dated observations. The comparison uses publicly described vendor functions, not independently tested vendor installations or a confirmed licence configuration. ORVIA evidence is from the customer-local `codex-a00` synthetic profile. ## What changed in ORVIA during this work window

Version 1 now has a non-model AI governance slice: tenant-scoped AI system and use inventory linked to purpose, processing activity, input asset, output system and processor; append-only risk, policy, control, evidence, monitoring, incident and separate-reviewer approval records; scoped API and workspace UI; reporting that distinguishes declaration from verification; and a durable input-inventory check job. The API integration run passed 32 assertions, including adverse and cross-tenant cases; the browser created and read back a synthetic use; and the actual monitor-worker run passed 9 assertions after the user authorized protected machine-identity setup. The monitor refuses to convert a staff-supplied `OBSERVED` label into independent evidence. No model or customer-data egress was added.

An additional synthetic PostgreSQL catalog discovery journey reads exact approved relation metadata through a least-privilege local observer. A separate reviewer approves the source, a durable job records the column snapshot and digest, and the workspace displays the observed result. The first adapter check passed 13 assertions; the initial API/worker check passed 30, including missing relations, cross-tenant denial, self-approval denial and exhausted retries. It reads no row values and does not classify personal data. This has not been run on a customer-controlled sandbox.

The later 0.25.0 build closes that graph trust gap on the synthetic target: a current catalog observation can create a dataset bound to its source receipt; staff cannot create an `OBSERVED` asset or relationship by assertion; direct database bypass attempts are rejected; and current inventory coverage excludes legacy unbound labels. A separately authorised source disable immediately removes current coverage and causes the AI monitor's next check to record a finding. Schema changes and exhausted catalog retries open durable review gaps. An observed dataset without a recorded processing activity raises a mapping gap for human review. The catalog/graph/AI monitor journey passed 58 assertions, including a reversible synthetic target schema change and cross-tenant gap isolation; the existing graph suite passed 46, coverage 56 on the new mapping rule, direct database guards 2, and browser creation/readback passed with no external requests or console errors. The AI monitor describes an independently read **input relation**, not external model behavior. This remains one PostgreSQL metadata adapter, not data classification or broad estate coverage.

## Platform reading of Section 2

ORVIA now has tangible local privacy-action and non-model AI governance journeys, including a narrow, independently read-back synthetic privacy effect. The published discovery, integration, framework and enterprise GRC breadth of OneTrust, BigID, Securiti, Vanta, Drata, Sprinto, Scrut, ServiceNow and MetricStream remains broader than ORVIA's verified scope. ComplyIQ publicly describes data mapping, ROPA, vendors and approvals; the other India-oriented and specialist names still require module- and deployment-specific demonstrations. ORVIA cannot responsibly claim platform superiority or lower cost from index listings. [ComplyIQ](https://comply.iqworks.ai/features/data-inventory)

The highest-value next proof is one approved real, read-only discovery integration followed by one safe controllable target action, independent readback, durable reconciliation, alert, evidence export and browser review on an identified candidate. The DPDP extension lane owns its separate paths; any shared application change requires coordination. The full T01–T34 application acceptance has **not** been produced for this work tree.
