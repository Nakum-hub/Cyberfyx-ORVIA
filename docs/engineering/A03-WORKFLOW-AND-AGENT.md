# A03 durable workflow and restricted agent

The outbox dispatcher submits a Temporal workflow named `orvia:<tenant>:<environment>:<event>` with duplicate reuse rejected. Temporal acceptance happens before the PostgreSQL delivery marker is committed. A crash between them repeats the same identity; it does not create another logical workflow. Workflow code contains only deterministic orchestration, bounded activity retries and durable timers. Activities create persisted immutable plans and signed commands, await persisted receipts, perform a separate scoped read and evaluate obligations.

The restricted agent is a separate process. It polls the frozen private command interface with an installation/environment-bound opaque machine credential. Human cookies, browser origins, incorrect installation/environment, unknown or expired credentials are denied. Credentials last one hour and are renewed only by the protected named-profile CLI. They are generated locally and stored outside Git. Customer execution signing uses a locally generated Ed25519 key; it has no relationship to vendor release/licence trust.

The agent independently checks schema, signature, enrolled installation/key/scope/system, capability/version, one-record budget, approval bindings and the persisted independent publication approval. It then locks the consent boundary, reads current epoch and mapping generation, locks the exact target row, rechecks expiry and mutates only that synthetic membership. A superseded epoch/generation produces a persisted failure without mutation. Grant records never automatically re-enable a target or create a fresh generation. A04 must deny processing through unresolved earlier suppression; A06 supplies the additional target-generation/recovery adversarial fixtures.

Only `orvia_target_agent` can update the separate target database, and only its protected local agent directory contains that role's password. The worker gets a SELECT-only observer credential. `orvia_worker`, `orvia_agent_control`, `orvia_machine_auth`, the application and the two human-auth roles are distinct, nonsuperuser, non-BYPASSRLS roles. Both control and target stores enforce scoped RLS. Provisioning uses the protected migrator; runtime code never loads that credential.

The target update and command ledger receipt commit in one target transaction. The ledger has unique command and nonce identities. Identical committed command replay returns the existing receipt, including after expiry, without running the effect again; changed-body reuse is rejected. A new command is checked against real current expiry both before locking and immediately before mutation. Reused nonces roll back the target transaction. This is the tested local idempotency protocol, not a universal exactly-once claim.

Consent mutation and agent effects acquire the same transaction advisory lock on `(tenant,legal_entity,principal,purpose)` before any target mutation. The command's epoch is re-read under that lock. A04 send admission uses the same lock. The target transaction commits before the control transaction releases it. If the control transaction/receipt fails after target commit, the durable target ledger supports replay; no missing response is treated as proof of no effect.

The worker observes through a separate SELECT using the observer role. `ACKNOWLEDGED` is retained as execution evidence. Only fresh `SCOPED_READ`, matching current epoch/generation, can satisfy the independent-observation criterion. Current workflow and portal receipt reads stop presenting an old completion as current after a new epoch; observations expire after five minutes. Unsupported/missing mappings remain unresolved obligations. Simulator faults and explicit uncertainty reconciliation are A05 work.

Working commands: `machine:init confirm:codex-a00` provisions/renews the named synthetic installation and seeds only missing mapped targets, preserving existing restrictions; `worker` runs dispatch and the real Temporal worker; `agent` runs the restricted poller; `test:workflows` runs actual HTTP configuration/consent, Temporal, worker process interruption/restart, agent mutation, independent observation and negative commands. Use the pinned `scripts/dev.ps1` wrapper, or `scripts/record.mjs` for evidence. Setup expires neither history nor restrictions and exposes no arbitrary database/URL/shell operation.

Application remains development loopback HTTP. TLS qualification, deployed process filesystem isolation, runtime egress proof, simulator faults, sender enforcement and guarded restoration are later increments. Do not label the entire prototype complete from A03.
