# Acceptance map: T01–T34 against the existing tests

**Purpose:** Phase B of Codex round 7 runs the 34 acceptance scenarios in `tracking/acceptance.json` on one frozen candidate. This map says, for each scenario, which existing suites already exercise which of its steps, and which steps have **no** test yet. Phase B then writes only the missing steps (`tests/acceptance/Txx-*.ts`) and re-runs the rest on the candidate, instead of rediscovering all of it.

**Status of this document:** planning aid, written 2026-09-30 by Claude Code from the test files' own headers and assertion names. It is **not evidence**. Nothing here changes a scenario from `NOT_RUN`. A scenario is `PASS` only when every expected step ran on the frozen candidate with an artifact (`docs/engineering/PRODUCTION_READINESS.md`, "Rules for status changes"). Where this map says "covered", read "a suite exists that should cover it; confirm on the candidate".

**Candidate:** `main` at `f940318` (merge of PR #36, contract 0.48.0, customer migration 0073), unless round 7 fixes produce a later one.

**How to run a suite on the codex-a00 profile:** integration and e2e suites with `scripts/run-signed-suite.sh <file>` (release keys from `.local/vendor/signing/release.json` in the environment); `tests/e2e/*.spec.ts` through the Playwright config in `tests/e2e/playwright.config.ts` (rehearsal profile for the TLS ones); unit suites with `pnpm test`. One suite at a time against one runtime (AGENTS.md "one writer").

Legend: **Covered**: existing suite(s) assert this step. **Partial**: related assertions exist but not the full step as written. **Gap**: no test found; write it.
