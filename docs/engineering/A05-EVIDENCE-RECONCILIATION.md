# A05: uncertain effects and independent evidence

The local REST simulator uses the canonical private machine routes. An AGENT credential can execute only an enrolled, signed exact-resource restriction; an independently enrolled OBSERVER can read state and provider receipts. Human sessions and the wrong machine kind cannot cross these mounts. The synthetic provider executes the same scoped/generation/epoch guards as the SQL agent. It is mounted in the local Next process for this prototype, with a separate target database and restricted target roles; process isolation of the provider is not claimed.

`fixture:simulator confirm:codex-a00 <resource-uuid> HEALTHY|UNAVAILABLE|APPLY_THEN_TIMEOUT|ACK_WITHOUT_EFFECT read|deny-read` changes the behavior of that enrolled synthetic REST target through protected local setup credentials. The fault selector does not select an observation or test result. APPLY_THEN_TIMEOUT commits the target mutation before delaying the HTTP response beyond the agent deadline. ACK_WITHOUT_EFFECT returns the provider acknowledgement without applying the target change. Fault controls have no public HTTP mutation endpoint.

The signed plan permits one automatic effect attempt. PostgreSQL command and delivery journals retain stable replay; transport/activity retries retain the same command. A failed or uncertain attempt requires attention. Unknown effects are not blindly retried. A separate authorized reconciliation request is stored with the action and its receipt, dispatched with a stable Temporal identity, and resumes after worker restart. Reconciliation performs a fresh independent read under the current consent boundary. It appends observation/reconciliation evidence, preserving the original EFFECT_UNKNOWN attempt. A provider receipt alone cannot satisfy CURRENT_SCOPED_OBSERVATION.

Observation reads use the exact resource and generation. Denied/unavailable reads append UNVERIFIABLE with no fabricated observation timestamp. Ordering uses persisted creation time, so a new unsuccessful read supersedes an older satisfied read. Current consent epoch, target generation and five-minute freshness determine current completion. REST send admission also exercises this observer mount: read-permission loss cannot be bypassed by an underlying SQL read. A failed capability check invalidates current workflow and portal completion immediately, while retaining prior observations as history. System checks expose actual read availability; `supports_restrict` remains the declared adapter capability, not a mutation probe.

MEMBER access requires both a server-verified staff session/MFA and a persisted workflow assignment, enforced by restrictive PostgreSQL policies. `fixture:assign confirm:codex-a00 <workflow-uuid>` assigns only the known synthetic member. A manual attestation records actor, statement, time and exact-workflow evidence references, and checks current epoch after the consent lock. It can meet only an explicitly declared ATTRIBUTED_MANUAL_ATTESTATION obligation. It does not produce an automated observation; a mandatory independent read remains unresolved. Fresh consent invalidates the old task's current completion.

Overview/failure/evidence endpoints derive their content from scoped persisted rows. Local JSON exports require read/export authority, are audited, and use attachment/no-store headers. The digest is tamper evidence relative to a trusted reference, not proof against privileged rewriting or legal certification. Unknown, failed, manual and unverifiable outcomes remain separate. Test-run linkage is empty until A06 supplies real persisted runs. The connector catalog reports NOT_RUN instead of inferring acceptance from implementation.

## Contract change A05-C01

Executable transport contract **0.4.0**, pending Work semantic review and Claude Code integration. `GET /api/v1/admin/control-map` now accepts the existing `cursor`/`limit` pagination parameters and returns `{edges, next_cursor}`. Consumers must continue until `next_cursor` is null; each page remains bounded to 100. The previous endpoint rejected scopes above 100 mappings, exposed by the retained synthetic test data. Generated OpenAPI, types, examples, seed and manifest change together. No alternate UI DTO is introduced. Signed command schema remains **0.3.0**, with unchanged cryptographic bindings and existing signatures; transport pagination does not invalidate queued commands.

Other A05 endpoints retain the already generated request/response shapes: `reconcile`, `attest`, `failures`, `overview`, `evidence`, `export`, `check_system`, `capabilities`, `restrict`, `read_simulator`, `read_simulator_receipt`. Examples and errors are in `packages/contracts/generated/examples.json`. Workflow polling must surface NEEDS_ATTENTION without interpreting it as successful completion.

## Installation and verification scope

Applied control migrations 0008–0012 and target migrations 0002–0003 are immutable. Fresh setup must run `roles:init confirm:<named-profile>` before `db:migrate`, then the existing auth/bootstrap/fixture/machine initialization commands. The new role command creates only compiled allowlisted unprivileged roles, checks an empty or matching synthetic database, preserves existing credentials, and grants no schema/table authority itself. Existing-profile execution is tested here; a clean profile installation is A07 qualification.

`test:evidence` exercises actual HTTP, PostgreSQL, Temporal, OPA, target mutations and observer reads; `test:workflows`, `test:auth`, `test:consent` and `test:expiry` are regressions. Test setup subprocesses are asynchronous so the HTTP client's event loop remains responsive. Earlier setup/permission/authentication failures remain in the evidence directory. No database reset, customer data, real message transport, browser acceptance, TLS or runtime-egress qualification is implied by A05.
