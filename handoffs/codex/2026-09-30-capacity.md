## Delivered

`scripts/capacity-mixed.ts` now returns a failing CLI status when query errors occur, records a PASS/FAIL result and classifies errors into statement timeout, lock timeout, client timeout or other, without logging SQL data. No fixture, workload weight, row count, concurrency, duration or timeout was weakened. No new migration was needed.

Root cause: the historical scope predicate casts UUID columns to text, distorting selectivity estimates. The old audit query uses a bitmap heap scan plus sort across many records despite an existing scoped chronological index. Current migration 0063 already changes scope comparisons to UUID values. The current-schema plan uses `audit_events_scope_time_id` as an ordered index scan (about 1.432 ms in the recorded pre-workload plan). The server and classified client errors explicitly identify statement timeout, not a lock timeout.
