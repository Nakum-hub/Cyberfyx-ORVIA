## Timeout evidence and concrete next diagnostic

`backend/authorization/src/index.ts:requireCapability` already has two transport attempts with individual 2-second deadlines. False policy decisions are denied without a retry. Vendor authorization in `backend/api/src/vendor/authority.ts` has one 2-second attempt. The admin transport retry can double dependency traffic during overload; it is an amplification mechanism, not a demonstrated cause. The inspected admin Rego consists of bounded role/capability rules, not record-sized data scans. Preserve policy denials and existing deadlines during diagnosis.

`database/customer/src/runtime.ts` supplies PostgreSQL statement_timeout 9000 ms and client query_timeout 10000 ms. PostgreSQL's statement deadline applies per statement: earlier bulk row work does not consume a shared transaction-wide 9-second budget. `backend/domain/src/operations/bulk-import.ts:processJob` performs the final audit after row processing, counters, job update, and completion emission; a failure there rolls back the transaction. `backend/domain/src/shared/transaction.ts:audit` inserts only metadata into audit_events. Its INSERT RLS checks scope and actor, and its scoped environment FK can acquire key-share locks. The append-only trigger is UPDATE/DELETE only, not an INSERT trigger. No audit-chain/advisory-lock trigger on INSERT was found.

Thus the reported audit INSERT cancellation requires its own elapsed-time/wait explanation. A later snapshot without blockers cannot exclude a transient blocker at the actual cancellation. The next bounded diagnostic should capture metadata-only pg_stat_activity PID, application_name, state, wait_event_type, wait_event, query_start and pg_blocking_pids continuously while the exact owned failing request is active, together with client audit-INSERT send/completion timing. Do not log SQL values or customer data. Correlate the timestamps with host free memory, process working sets, event-loop delay and Docker CPU/memory, and host-versus-VM OPA response duration on the same interval. A single no-contention control of the exact request is useful only after this capture defines the comparison; a passing rerun alone is not a root cause.

The parent's reported OPA idle latency versus >2-second loaded latency, and reproduction under minimal instrumentation, support load sensitivity but do not identify whether host scheduling, proxy transport, container scheduling, or application event-loop delay is responsible. Do not label verbose tracing, PostgreSQL locking, memory pressure, or OPA evaluation as proven causes yet.
